## 라운드 내부 순서
| 단계 | 예정 시간 | 구현 원칙 |
|---|---|---|
| 시나리오 + Risk 확인 | 3분 | 원문 + RMC 3문항 |
| 자유 열람 | 5분 | 12명 비교 가능, 선정 기준 열람 가능, 프로필 오가며 비교 |
| 초기 판단 | 2분 | 한 명씩 순차, 적격/부적격, 진행 수 n/12 표시. AI 등장 전까지 검토·수정 가능, 12개 확정 시 잠금 |
| AI 제시 | 10초 + 2분 | 10초 중립 대기 → 권위 안내·배지 + 12명 AI 판정 + 배정 설명 |
| 최종 판단 | 2분 | 같은 순서로 12명 재판단. 초기 판단은 읽기 전용 표시, 새 선택은 명시적으로 받음(초기값·AI값 자동 선택 금지). AI 재열람 경로 제공 |
| 의존 지표 계산 | — | 서버 저장값에서 산출, 참가자 응답 없음 |
| Trust | 1분 | 해당 라운드 S-TIAS 3문항 |

## 시간 규칙 (권고안 적용)
- 시간은 "예정 소요 시간"으로 안내한다. 강제 종료하지 않는다.
- 초과 시 초과 시작 시각을 기록하고 계속 진행하게 한다.
- 시간 종료로 무응답을 부적격으로 확정하지 않는다.
- 12개 미완료 상태로 제출하면 미응답 위치를 알려 준다.
- 모든 시간 값(10초 대기 포함)은 설정 파일 한 곳에서 관리한다.

## 배정과 순서
- 12셀 = authority(2) × explanation(3) × risk_order(2). 서버의 DB 함수에서 균형 블록으로 원자적 배정. 동시접속 30~50명에서도 중복 배정 없음.
- 배정은 처음 한 번만 저장. 새로고침·재접속 시 같은 조건·순서·시드 복원.
- 프로필 표시 순서는 라운드별 별도 시드로 무작위화하고, 한 라운드 안의 모든 단계에서 유지.
- 두 라운드 사이 조건 불변. 정답·점수 피드백 없음.

## 상태와 복구
- 실험 진행은 서버 상태 기준의 상태 머신이다. 클라이언트는 현재 단계를 서버에서 받아 렌더링한다.
- AI 노출 이후 초기 판단 화면으로 돌아갈 수 없다(뒤로 가기·URL 직접 접근 포함).
- 초기 판단 잠금 트랜잭션이 성공한 뒤에만 서버가 AI 페이로드(A, fi, case)를 반환한다.
- 다중 탭, 중복 제출, 네트워크 복구 후에도 원자료가 보존되어야 한다.

## 화면 규칙 (조건 간 동일 요소)
| 단계 | 필수 요소 | 조건 간 동일하게 유지 |
|---|---|---|
| 시나리오 | 원문, 위험 3문항 | 본문·문항·시점·예정 시간 |
| 자유 열람 | 12명 비교, 선정 기준 열람 | 특성 순서 E/P/R/T, ID·나이 |
| 초기 판단 | 한 명씩 적격/부적격 | 응답 버튼, 표시 순서, 진행 수 |
| AI 제시 | 10초 대기 뒤 추천과 배정된 조작 | 추천 A, 색·크기·레이아웃 |
| 최종 판단 | 초기 판단 읽기 전용 + 새 최종 선택 | 순서·선정 기준·AI 재열람 경로 |
| Trust | 3문항 | 문항·척도 |

- 인터페이스는 중립적이고 단순하게. 장식 요소 추가 금지.
- 조건별 시각 차이는 AuthorityCue, Explanation 컴포넌트에만 존재.
- 색상만으로 적격/부적격이나 기여도 부호를 구별하지 않는다.
- 키보드 이동, 초점 표시, 스크린리더 라벨 제공.
- 기준 환경: 대면 PC, 1280×720 이상. 200% 확대에서 정보 누락·가림 점검.
