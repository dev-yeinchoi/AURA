# 00. 미결 사항과 검토 메모 (Phase 0 rev08 기준)

이 문서는 개발 중 "추측하지 말고 질문"해야 하는 지점의 목록이다. 아래 항목은 코드에서 **설정값·데이터·플레이스홀더**로 분리해 두고, 확정되면 해당 값만 바꾼다. 항목이 확정되면 이 문서에서 지우고 해당 docs 문서에 반영한다.

## A. 계산 검증 결과 (확정)
- 24개 프로필의 G·A·유형, 라운드별 TP3·FP2·FN2·TN5, Shapley 기여도(합 = A 출력, φT = 0), 비교 사례 매핑을 독립 재계산하여 rev08 표와 모두 일치함을 확인했다.
- 기준값: `data/stimuli/low.json`, `data/stimuli/high.json` (생성기: `scripts/generate_stimuli.py`). TS 규칙 함수는 이 파일을 정확히 재현해야 한다.

## B. 본 실험 전 연구자 결정이 필요한 설계 이슈 (개발 차단 아님 — 데이터 교체로 대응)
1. **비교 사례(Case)와 AI 판정의 불일치**: 현재 규칙(세 특성 거리 최소, 동률 시 작은 ID)에서는 AI가 적격으로 추천한 5명 중 사례의 AI 판정이 같은 경우가 Low 2명(L02, L05), High 1명(H04)뿐이다. High의 TP 3명은 모두 "부적격" 사례가 함께 제시된다. 또 L01은 16개 사례가 모두 동률이라 사례 선택이 동률 규칙에만 의존한다. 그 결과 (a) FI+Case 조건에서 설명 내부가 추천과 상충하고, (b) 일치 비율이 Low/High 맥락 간에 달라 위험 맥락과 설명 내용이 섞일 수 있다. 수정안 예: 후보를 "대상과 A 판정이 같은 사례"로 제한(G·정답 여부는 계속 사용하지 않음), 또는 경계값과 동률이 생기지 않는 사례 집합으로 교체. 결정 시 `scripts/generate_stimuli.py`만 바꾸고 JSON을 재생성한다.
2. **초기 정확도 천장 위험**: 참가자에게 G 규칙 전체가 공개되므로 주의 깊은 참가자는 초기 판단에서 12명을 모두 맞힐 수 있고, 이 경우 RAIR 분모가 0이 된다. 문서의 예비실험 기준(분모 0 비율 > 25% 또는 중앙 기회 수 < 2이면 재검토)으로 확인한다.
3. **선정 기준 문구의 위험별 표기**: 공통 문구가 "6회·6건", "[2/4]시간"처럼 두 맥락을 함께 표기한다. 화면에는 맥락별로 하나만 보이게 렌더링할지(권장) 연구자 확인이 필요하다. 현재 구현 기본값: 맥락별 렌더링.
4. **용어 통일**: Low 시나리오 원문은 "동아리원", 공통 응답 안내는 "직원"을 사용한다. 원문은 고정이므로 수정하지 않되, 프로필 카드 라벨을 무엇으로 할지 확인 필요. 현재 기본값: "직원".

## D. 운영 전 확인 (배포 관련)
- Supabase Free 플랜은 7일간 활동이 적으면 프로젝트가 자동 일시정지된다. 데이터 수집 기간에는 Pro 플랜을 쓰거나, 실험일 전날 반드시 접속 확인한다.
- Supabase의 레거시 anon/service_role 키는 2026년 말 폐지 예정이므로 처음부터 publishable/secret 키만 사용한다.
- 배포 후 Vercel 배포 요약에서 함수 리전이 icn1인지 확인한다.

## E. 범위 밖 (플랫폼이 다루지 않음)
- 신청 단계(이름·전화번호·가능 시간)와 사례비 지급 관리: 연구 응답 DB와 분리된 별도 자료. 플랫폼은 가명 participant_id만 다룬다.
- 분석 모형, 검정력 시뮬레이션: 원문 rev08 §9 참조. 플랫폼은 원자료와 분모·결측 사유를 정확히 남기는 것까지 책임진다.
